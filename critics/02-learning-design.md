# 02 Learning design

Lens: does the plan teach, by what is known about how people learn? A plan can run on time, be fun and still leave nothing behind. This critic checks that each idea is introduced once, practised, recalled and transferred, in that order, with the load kept inside what the band can hold.

## Checks

- **Backward design:** the outcome is a verb phrase someone can watch (make, sort, fix, explain to a partner with the right terms), not "understand" or "be familiar with". Walk each segment back to it: a segment that does not move the learner toward the outcome is a finding, however good it is on its own.
- **One idea per learn segment:** each learn segment introduces exactly one new idea. Two ideas in one segment, or an idea that arrives inside a try segment without its own learn, is a finding. Severity 2 when the second idea is needed by the outcome; 3 when it is a tangent that could be cut.
- **Cognitive load:** count the new terms per segment; more than three is a finding. Every abstraction is preceded by an analogy from the learner's world, and every independent task is preceded by a worked example the learner watched or read all the way through. Note where a segment asks the learner to hold a procedure in their head that could be on a card.
- **Scaffolding fades:** try is guided (steps shown, example given, partial answer supplied); apply is not (the learner chooses the moves). A plan where try and apply have the same level of support has no fade; a plan where apply is still step-by-step has no independence.
- **Retrieval practice:** before a learn segment tells the learner the answer, the learner has been asked to produce one (a prediction, a guess, a draft). Later in the lesson at least one point asks them to recall it again with the material out of view. Re-reading or a slide recap is not retrieval.
- **Spacing:** each key concept returns at least twice after its learn segment, with something between the returns (a try, an apply, a check). In course mode the concept also returns in a later lesson.
- **Misconceptions:** the teacher notes name the two or three ways learners typically get this wrong, and for each the one line that fixes it. "Common mistakes: various" is a finding. A misconception named with no fixing line is severity 3; a predictable misconception not named at all, when the check segment depends on it, is severity 2.
- **Feedback in try:** every try segment gives the learner a result within seconds (a reveal, a score, a comparison to a model answer) and the result says what was wrong, not only that it was. End-of-lesson marking is not feedback for a try segment.
- **Check measures the outcome:** the check segment asks the learner to do the outcome's verb on something new, not to recognise the right answer among four. Multiple choice measures a different thing from "can make". Self-rating is not a check (critic 01 flags the missing evidence; log it here when a check exists but measures recognition).
- **Transfer:** the apply segment uses material that differs from try in surface features (a different document, dataset, story, object) while needing the same move. If apply is try with the names changed, nothing has transferred.
- **Active ratio:** active minutes (try, apply, check) against passive minutes meet the band's rule in `taste/age-bands.md` (1:1 for E and above, 2:1 for A–C).

## Course mode (`/lesson course`)

- **Progression:** each lesson's prior knowledge matches what earlier lessons' outcomes produced; no lesson assumes a skill no earlier lesson built.
- **Spacing across lessons:** every concept taught in lesson N is retrieved in at least one later lesson, not only in the lesson that taught it.
- **The artifact chain:** every artifact a lesson produces is used as input to a later lesson, and the later lesson's materials table names it. An artifact nothing uses again is a finding.

## Anchors

- **4:** the outcome is "understand" or "know"; at least one learn segment carries two or more new ideas; the learner is told before being asked; try and apply are the same task with the same support, or apply is missing; the check is recognition or self-rating; no misconceptions are named.
- **7:** the outcome is observable and the segments serve it; one idea per learn segment with an analogy; try is guided and apply is independent; the learner predicts once before being told; feedback in try is immediate; the check does the outcome's verb; one gap remains: a concept returns only once, or misconceptions are named without their fixing lines, or apply sits too close to try.
- **9:** the plan has every new term counted and under three per segment; a worked example before every independent step; retrieval before and after every key idea, with the material out of view the second time; apply on material that differs from try in every surface feature; each misconception named with its fixing line and the segment where it surfaces; the check is a fresh performance of the outcome that would convince a sceptical colleague.

## Mode notes

- **live:** retrieval can be spoken (ask the room before telling it); feedback can come from a partner holding a model answer.
- **online:** every retrieval point is an input the app records; feedback is automatic and specific to each wrong answer, not one generic "try again".
- **video:** the viewer cannot be made to recall; the plan asks a question and leaves a visible pause long enough to think before answering.
- **guide:** worked example means the full expected output shown before the learner's own attempt; retrieval means "before you scroll, write down what you expect to see".
- **talk:** one idea per ten minutes, one audience prediction before each reveal; a talk with no room for a try segment still has one moment where everyone writes something down.
