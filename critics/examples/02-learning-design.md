# 02 Learning design: examples

Fictional plan segments for calibration. Scenario throughout: a band E live lesson (office workers, 7–30 people) whose outcome is "write a request that gets the assistant to turn raw meeting notes into a one-page summary with owners and dates". Learner-facing lines are in Korean per the example house rules; teacher notes in English. Nothing here is real data.

## 4

> **S2 learn (12 min):** Teacher explains what a prompt is, the four parts of a good request (role, task, format, limits), and how the assistant reads context. Slides 3-9.
> Instruction: "오늘은 요청문을 잘 쓰는 법을 이해해 봅시다."
> **S3 try (10 min):** Learners write a request for the sample notes using the four parts.
> fast / slow / wrong: circulate.
> **S4 apply (10 min):** Learners write a request for the same sample notes, this time on their own.
> **S5 check (3 min):** "오늘 내용, 얼마나 이해하셨나요? 1-5점으로 표시해 주세요."

Why a 4: "이해" as the outcome, three ideas in one learn segment, told before asked, apply is try again on the same notes, no model shown, and the check is a self-rating (ladder step 1).

## 7

> **S1 hook (4 min):** Screen shows a finished one-page summary with owners and dates. "오늘 마지막에 여러분 회의록으로 이런 요약을 직접 만들어 가십니다." Each learner writes on a card what they would type to get it.
> **S2 learn (6 min):** One idea: the format line. Worked example on sample notes A, built line by line; one weak request beside it, and the class says which line is missing.
> **S3 try (8 min):** Complete a half-written request for notes A (last two lines blank). A three-item checklist is shown before starting; the model answer is revealed after, and partners compare line by line.
> fast / slow / wrong: add a limits line / hint card with the format line started / "format missing" goes back to the weak example.
> **S4 apply (12 min):** Learners write a request from scratch for their own last meeting notes (or sample notes B, a sales call).
> **S5 check (5 min):** Each learner writes a request for unseen notes C; the teacher checks it against the S3 checklist.

Why a 7: observable outcome told to the learner, finished result first, prediction before telling, a non-example, guided try with immediate feedback, independent apply, check at ladder step 5; gaps: no opening review, no self-explanation prompt, no branch for weak check results.

## 9

> **S1 review + hook (5 min):** "지난 시간에 배운 '역할 한 줄'을 카드에 적어 주세요." All hold up cards; the teacher reads the room. Then the finished summary is shown: "이 요약을 여러분 회의록으로 만드는 것이 오늘의 목표입니다. 다음 주 회의부터 바로 쓰실 수 있습니다."
> **S2 learn (6 min):** Labelled pre-question first: "틀려도 괜찮습니다. 먼저 짐작해 보시면 더 오래 기억됩니다." Then a worked example, with two non-examples (no format line; a format line but no owners).
> **S3 try (8 min):** Completion request on notes A, criteria card shown first. Feedback: "형식 줄이 없습니다. 담당자와 날짜 칸을 넣어 다시 보내 보세요." No scores. Prompt: "왜 형식 줄이 담당자를 빠뜨리지 않게 해 줄까요? 한 문장으로 적어 주세요."
> **S3b hinge (2 min):** Four options, each wrong one a named misconception (M1 longer is better, M2 the assistant remembers last week, M3 politeness sets the format). Everyone holds up A-D. Mostly wrong: replay the non-example; mostly right: go on.
> **S4 apply (12 min):** Own notes, from scratch. Before sending: "제 요청문에서 기준에 맞지 않는 줄 하나를 찾아 고쳐 주세요."
> fast / slow / wrong: two meetings in one summary / starter card / route by misconception id.
> **S5 check (5 min):** Unseen notes C (a different team, a different note style). Weak result: tomorrow's online opener repeats the format line; strong: extension card.

Why a 9: review of earlier learning, whole task first, objective and purpose told, labelled pre-test, examples and non-examples, criteria before the task, next-step feedback with no grade, self-explanation, own-error diagnosis, a hinge that changes the path, transfer on new surface features, ladder step 5 with a branch.

## Pairs

- **Backward design:** good: "각자 회의록으로 담당자와 날짜가 있는 요약 요청문을 쓸 수 있습니다." / bad: "요청문 작성법을 이해합니다."
- **Plan told to the learner:** good: the opening screen says what they will make and that they can use it at next week's meeting / bad: the objective appears only in the teacher notes.
- **Opening review of earlier learning:** good: everyone writes last lesson's role line on a card before anything new / bad: the lesson opens with "오늘 배울 내용은..." and a list of today's topics.
- **Whole task shown first:** good: the finished one-page summary is on screen before step one / bad: step one starts with "먼저 역할을 적습니다" and the end product appears only in S5.
- **One idea per learn segment, practice after each:** good: S2 teaches only the format line, then S3 practises it / bad: S2 covers role, task, format and limits, then one try at the end.
- **Demonstration matches the goal type:** good: the concept "a complete request" is taught with one example and two non-examples / bad: three good examples and no request that fails.
- **New terms (house default):** good: S2 introduces only "형식 줄", defined and used in the same minute / bad: S2 introduces prompt, context window, token, role and format with no definitions (severity 2: undefined and unused).
- **Worked examples and analogies fit prior knowledge:** good: the brief says learners already write such requests weekly, so S2 shows a contrast case and S3 is a full problem / bad: same brief, and S2 walks through a ten-step worked example of a task they do every week.
- **Scaffolding fades:** good: try has the last two lines blank; apply starts from an empty box / bad: apply gives the same four-part template as try.
- **High success in guided practice:** good: try is a completion problem most can finish with the checklist / bad: try asks for a full request in a format nobody has seen, with no pre-test label.
- **Retrieval practice, graded:** good: learners write a guess before the reveal, and S5 asks for the format line from memory / bad: "슬라이드를 다시 한번 읽어 보세요" as the review step.
- **Spacing:** good: the format line returns in S3, the hinge, S4 and S5 / bad: the format line appears in S2 and never again.
- **Interleaving only for telling apart:** good: the outcome is choosing between a summary request and a draft-email request, and later practice mixes the two / bad: the outcome is one procedure and the very first try mixes three request types.
- **Self-explanation:** good: "왜 이 줄이 필요한지 한 문장으로 적어 주세요." / bad: "짝과 이야기해 보세요." with no prompt.
- **Misconceptions:** good: "M1 longer is better. Fix line: the format line matters more than length. Surfaces in S3." / bad: "Common mistakes: various."
- **Success criteria before the task:** good: a three-item checklist and a model request shown before S3 starts / bad: the checklist appears only in the marking notes.
- **Feedback says what to do next:** good: "담당자 칸이 없습니다. 형식 줄에 '담당자'를 넣어 다시 보내 보세요." / bad: "7/10, 형식을 보완하세요."
- **Learner finds their own error:** good: "기준에 맞지 않는 줄 하나를 찾아 고쳐 주세요." before any marking / bad: the teacher underlines every error for them.
- **Paths for fast, slow and wrong learners:** good: fast gets a two-meeting extension, slow a starter card, wrong is routed by misconception / bad: "fast / slow / wrong: circulate."
- **Check ladder:** good: unseen notes C, request written alone, judged on the checklist shown in S3 (step 5) / bad: "이해하셨나요?" with thumbs up (step 1).
- **Hinge questions mid-lesson:** good: four options, each wrong one a named misconception, all answer at once, the next segment depends on the spread / bad: a mid-lesson quiz with joke options and no change of plan.
- **Check-result branch:** good: a weak result means tomorrow's opener repeats the format line; a strong one means an extension card / bad: exit cards collected, nothing said about what happens next.
- **Transfer:** good: try on a project meeting, apply on the learner's own notes, check on a sales call / bad: apply uses the same meeting notes with the names changed.
- **Active ratio (house default):** good: the finding quotes the band E 1:1 rule as a house default and counts the questioning learn segment as partly active / bad: a severity-1 finding because passive minutes exceed active minutes by two.
